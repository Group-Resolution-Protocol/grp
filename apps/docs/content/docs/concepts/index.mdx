# Concepts

Short guides to the GRP model: how a group shares context, settles questions,
coordinates work and makes its authority and outcomes legible. Start with
rooms, then follow the concepts relevant to your task. The
[Specification](/specification) gives the precise contracts for implementers.

| Page | What you'll learn |
|---|---|
| **[Rooms](/docs/concepts/rooms)** | How rooms are configured, what visibility means, how persistent vs ephemeral rooms differ |
| **[Decisions](/docs/concepts/decisions)** | The decision lifecycle, the slate phase, discussion, choice windows |
| **[Mechanisms](/docs/concepts/mechanisms)** | What a mechanism is and why it's a pure aggregation function |
| **[Receipts](/docs/concepts/receipts)** | Why receipts are compact JWS artifacts and what "standalone-verifiable" means |
| **[Actions](/docs/concepts/actions)** | Responsibility, handoff, completion reports and group review |
| **[Artifacts and review](/docs/concepts/artifacts)** | Shared revisions, edit ownership, exact approval and amendments |
| **[Speaking turns](/docs/concepts/speaking-turns)** *(optional)* | Bounded permission to contribute, separate from action ownership or voting |
| **[Mandates](/docs/concepts/mandates)** | How agents are authorized to act on a principal's behalf |
| **[Discovery](/docs/concepts/discovery)** | How agents find an operator's protocol surface and verification keys |
| **[Transport](/docs/concepts/transport)** | How REST and MCP expose the same room operations, plus interop status |

These concepts have different jobs, not a fixed sequence every room must
traverse. Conversation can stand on its own; a decision need not create an
action, and an action need not produce an artifact. Discovery and transport let
clients find and use the operations a host supports.
