# Publishing House evidence trial

Six separately signed-in agents operate one fictional publishing cycle through
three overlapping rooms and one private Git repository. They must commission a
serial, write and accept its opening, approve a launch plan, reconcile the
books, and integrate the authorized work.

## Paper observations

The paper block contains four independent fresh-session observations:

1. messages-only rooms;
2. GRP conversation rooms with decisions disabled;
3. ordinary GRP rooms with no preopened decisions; and
4. GRP rooms with task-appropriate configured decision surfaces.

The previously completed canonical six-account production run and the earlier
Publishing House Stage A/B trials remain development history. They are not
promoted into the paper. By principal ruling, this prospectively frozen block
runs directly as paper evidence without duplicating four rehearsal rooms. A
clean first attempt is final. A genuine setup, provider, product, operator, or
capture defect reopens only the affected observation.

## Frozen common work

Every observation keeps the same company seed, six accounts, role packets,
task, room topology, model, effort, finish line, evidence instruments, and
75-minute safety cap. Only the communication surface, connection block, room
configuration, fresh sessions, room identifiers, invitation tokens, and fresh
repository baseline differ.

The three rooms are:

- **Greenlight:** Silica, Cobalt, Argon, Mica, Neon, and Quartz;
- **Editorial:** Silica, Mica, Neon, and Quartz; and
- **Launch:** Silica, Cobalt, and Argon.

## Files

- [`seed/`](seed/) — neutral company repository baseline.

## Operator rules

- Use the standing Silica, Cobalt, Argon, Neon, Quartz, and Mica accounts in
  their existing six-window grid. Never open, close, move, resize, maximize,
  tile, replace, or rearrange a browser window.
- Before each arm, create fresh sessions through the existing sidebar and
  verify the exact registered private repository baseline, Opus 5, high effort,
  a blank composer, and no running work in one batch.
- Run the exact no-tools provider readiness prompt in all six sessions before
  any room or invitation exists. Discard the batch unless all six return
  exactly `READY`, finalize, and become idle.
- Create the rooms and named invitations as operator setup. Give each seat only
  its own intact connection blocks. Send each complete task packet atomically
  once. Do not send any participant another message during the live task.
- Do not assign tasks, appoint a chair, suggest a decision procedure, explain
  commands, repair Git or GRP use, wake a quiet seat, or name a final marker.
- End at the first all-idle, no-background, no-pending-transition observation
  followed by two quiescent room snapshots and a quiescent repository snapshot.
  The 75-minute limit is only a hard safety cap for unfinished work.
- Run the memory survey before resetting any participant session. A blind judge
  uses a separate fresh session after the surveys; it receives only the frozen
  transcript and repository evidence.
- Keep invitation tokens, credentials, private raw session material, and
  unredacted private transcripts out of reports. Verify every issued receipt
  standalone.
